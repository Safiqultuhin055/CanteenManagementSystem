System architecture

CanteenSys is a three-tier application: clients (browser, POS, kitchen TV, token display) → Django 6 (business modules) → SQL Server (data, stored procedures, reporting views).

Request path: User signs in → session + menu permissions → module view → ORM or stored procedure → CanteenManagementDB → response rendered with Bootstrap UI.

Operational sequence

  1. Login — usp_ValidateUserLogin, password check, session + login_history.
  2. POS — RFID scan → usp_ValidateEmployeeCard → cart → usp_ProcessEmployeeSale.
  3. Kitchen — order in kitchen_queue; status PENDING → PREPARING → READY.
  4. Distribution — token display; verify → usp_CompleteDistribution → PICKED_UP.
  5. Reports — read from SQL views (vw_*) for sales and inventory.

Run and deploy

1 python -m venv venv → pip install -r requirements.txt
2 Configure .env and run SQL scripts in SSMS.
3 python manage.py runserver 127.0.0.1:8000
4 Login: /users/login/ — Settings: /settings/ — Technical doc: /help/technical/

Security

  • Menus: users.permissions.get_menu_tree_for_user()
  • Technical docs: TECH_DOC_VIEW or admin role
  • Login lockout via usp_RecordLoginFailure + system_settings
  • Password change: usp_ChangePassword + password_history
  • Production: DEBUG=False, HTTPS, strong SECRET_KEY
